# X4 Sektorbau

Ein Wirtschafts- und Aufbauspiel für das Handy im Universum von **X4: Foundations**.
Kein Raumschiff-Steuern, sondern das, was X4 im Kern ausmacht: Stationen bauen,
Produktionsketten planen, Versorgungslinien ziehen, handeln und in neue Sektoren expandieren.

Du startest in **Familie Zhin** kurz nach dem Xenon-Angriff – mit einer kleinen Station,
einem Solarkraftwerk und einem Miner.

## Spielen

- **Online:** nach dem ersten Push auf `main` baut GitHub Actions das Spiel und veröffentlicht es
  auf GitHub Pages (einmalig in den Repo-Einstellungen unter *Pages → Source* „GitHub Actions“ wählen).
- **Bauen:** `npm run build` legt das Spiel in `dist/` ab – `index.html`, Code und alle Bilder als eigene Dateien
  in `dist/assets/` (Bilder werden erst geladen, wenn sie gebraucht werden, und bleiben im Zwischenspeicher).
  Zum Ausprobieren braucht es einen Webserver, z. B. `npm run preview`.
- **Trailer:** `node scripts/trailer/trailer.mjs <ordner>` nimmt einen Trailer direkt aus dem Spiel auf (Hochformat
  1080×1920, 60 Bilder/s, Bild für Bild mit angehaltener Uhr, Schnitte auf den Takt von „kampf-invasion“, Texte im
  Spielstil) und setzt ihn mit ffmpeg zur MP4 zusammen. Braucht die Schriften `@fontsource/barlow` und
  `@fontsource/chakra-petch` (Ordner über `TRAILER_FONTS`) und ffmpeg (`FFMPEG`); `--preview` macht nur Stichbilder,
  `--only=szene1,szene2` nimmt einzelne Szenen neu auf (mit `--encode` danach wieder zusammensetzen).
- **Sicherungen:** Beim Spielen wird alle 20 Minuten und bei jedem Start automatisch gesichert (IndexedDB im Browser;
  es bleiben die letzten zehn und je Tag eine der vergangenen zwei Wochen). Mehr → Spielstand → „Automatische
  Sicherungen“ zeigt sie und stellt sie wieder her (der aktuelle Stand wird vorher selbst gesichert). Fehlt der
  Spielstand beim Start, bietet der Willkommensdialog die letzte Sicherung an. „Spielstand sichern“ liefert eine
  vollständige Sicherung – Spielstand, Minispiel-Rekorde, Modteile, Ausrüstung, Einstellungen – als Text oder Datei;
  „Spielstand laden“ nimmt sie (und alte Spielstände) wieder an.
- **Schneller Start:** Die Minispiele sind eigene Programmteile und werden erst beim Start eines Spiels bzw. drei
  Sekunden nach dem Spielstart im Hintergrund geladen (Startdatei ein Drittel kleiner).
- **Eigene Adresse (Netlify):** `netlify.toml` beschreibt den Bau (`npm run build`, Ordner `dist`, Node 22) und die
  Zwischenspeicher-Regeln (Seite und Service Worker immer frisch, `assets/` dauerhaft). Netlify ist mit dem
  GitHub-Projekt verbunden, baut aber nur bei Commits mit `[live]` in der Meldung (`scripts/netlify-ignore.sh`) –
  jeder Bau kostet Credits.
- **Feedback von Testern:** Mehr → „Feedback geben“ und im Pausenmenü jedes Minispiels: Art (Fehler, Idee, Gedanke),
  Text, freiwillig Name, Bildschirmfoto (bei Fehlern vorausgewählt) und auf Wunsch der Spielstand; dazu automatisch
  Spielversion (Datum · Git-Stand), Gerät, Bildschirm, Ort im Spiel und Spieltag/Credits/Kapitel. Gesendet wird an
  Netlify Forms (Formular „feedback“, Gerüst `public/__forms.html` für die Erkennung beim Bau); Meldungen stehen im
  Netlify-Projekt unter „Forms“, auf Wunsch per E-Mail. Außerhalb der App-Version (Artifact, Einzeldatei) lässt sich der
  Text kopieren. Ein angefangener Text bleibt als Entwurf erhalten.
- **Startschirm bei jedem Start (überall, auch im Artifact):** Sprungtor scharf vor unscharfem Nebel, langsame
  Kamerafahrt, pulsierender Wirbel, Logo mit Lichtschweif und Glanz, Spielknopf mit Wellen. „Antippen zum Starten“ –
  erst die Berührung erlaubt Ton, die Titelmusik setzt damit ein. Ohne fälligen Trailer fliegt die Kamera ins Tor (Lichtblitz)
  und das Spiel beginnt.
- **Trailer (nur App-Version):** nach dem Startschirm (`public/intro/trailer-1.mp4`, 1080×1920, 60 fps, ~24 MB; einmal
  ganz geladen und vom Service Worker zwischengespeichert). Beim allerersten Start ganz, danach höchstens einmal am Tag
  und überspringbar; Einstellungen → Darstellung: „Trailer beim Start“ an/aus und „Trailer jetzt ansehen“. Klangteppich
  und Titelmusik warten, bis er vorbei ist. Neue Fassung = neuer Dateiname (`TRAILER_URL` in `src/ui/intro.ts`).
- **Kopfleiste (zwei Zeilen):** Oben eine gebündelte Leiste: rundes Sektorbild, Name und Spielzeit (antippen:
  Sektorenkarte), **Sektorinfo** (Baulizenz, Details, Späher und Erkundung direkt im Sektor), Credits (Kontobuch),
  Pause/Tempo, Warnungen. Darunter Nachrichten (Sprechblase), Menü (Zahnrad), die Eigenheit des Sektors als Knopf
  (z. B. „Sturm · 34 min“) und rechts der Knopf für die Kartenebenen (Handelsrouten, Warenflüsse) neben dem Zoom. Neue
  Stationen gründest du unten unter „Stationen“.
  Ansehen: `node scripts/hud-shot.mjs <ordner>`.
- **Sektorinfo in drei Reitern** (ⓘ in der Kopfleiste, Sektor auf der Sektorenkarte antippen oder Detailseite – überall
  gleich gegliedert): **Allgemein** (Beschreibung, Eigenheit, Sonne, eigene Stationen und Schiffe, Ruf, Baulizenz mit
  Kaufknopf), **Wirtschaft** (Rohstofffelder als Kacheln, Schürfrechte, gefragte und günstige Waren, Preise, Marktdaten
  je Quadrant mit Satelliten), **Erkundung** (Logbuch-Fundstück, Späher kaufen, peilen und schicken, Torbaustellen,
  Horchposten, Forschungsakte; ein Punkt am Reiter zeigt laufende Suchen und Baustellen). Der gewählte Reiter bleibt.
  Ansehen: `node scripts/sectortabs-shot.mjs <ordner>`.
- **Sektorenkarte:** „Sektor“ unten erneut antippen (oder oben auf den Sektornamen). Ruhiger, dunkler Grund: vier eigene
  Weltraumbilder (`src/assets/karte/hintergrund-1…4.jpg`), je 30 s, dann 8 s fließende Überblendung ins nächste, Sektoren als Glas-Sechsecke mit eigenem Farbschimmer und Sternenstaub –
  bewusst ohne Sektorbild, die Überraschung bleibt für den Besuch –, nur der Name. Eigene Sektoren leuchten türkis
  (orange bei Problemen), ein Winkel zeigt, wo du bist. Sprungtore als Verbindungslinien mit Torringen (eigene mit
  Verkehr, ins Unerforschte gestrichelt), Unerforschtes nur als Umriss. Tipp zeigt eine Karte (eigenes Gebiet mit Bild,
  sonst Farbschimmer) mit „Hinfliegen“ und „Details“/„Baulizenz“.
- **Unbekannter Raum (im Aufbau):** Über dem Split-Raum liegen 19 neue Sektoren in vier Gebieten (Glutsee, Schweigendes
  Band, Kristallgrenze, Abgrund – `src/data/frontier.ts`). Sie stehen erst auf der Karte, wenn sie entdeckt sind
  (`state.frontier.discovered`); gefundene Torsignaturen (`state.frontier.signatures`, „von>nach“) zeigen als gestrichelte
  Linie mit pulsierendem Signal ins Leere. Die Karte hat eine eigene Anordnung (Split-Raum unten, `SPLIT_MAP_POS`), weit
  entfernte Tore nur dort, wo sie keinen Sektor schneiden (Test); sie passt sich der bekannten Fläche an und lässt sich
  verschieben.
- **Späher und Suche (`src/engine/explore.ts`):** Späher (140.000 Cr) über die Sektorkarte kaufen und zu einem Sektor
  schicken: Flug Tor für Tor (20 min je Tor), dann 15 min Suche nach Torsignaturen ins Unbekannte. Die Hürde ist Können,
  nicht Geld: ohne Peilung 30 % Fundchance, eine volle Peilung findet eine vorhandene Signatur sicher. „Keine Spur“ heißt
  Pech oder wirklich nichts – das verrät die Suche nicht. Auf der Karte fliegt der Späher als Leuchtdreieck, bei der Suche
  kreist ein Radar über dem Sektor.
- **Peil-Minispiel (`src/ui/peilung.ts`):** „Peilen und schicken“ öffnet ein Radar mit zwei Wischfeldern unter Radar
  und Welle, für zwei Hände gleichzeitig: links die Richtung der Antenne, rechts die Frequenz (die Antenne lässt sich auch
  direkt auf dem Radar ausrichten). Verstimmt schwebt die Welle und das Signal bleibt zu
  schwach. 6 s gehalten = volle Peilung (35 s Zeit); wer das Signal verliert, verliert langsam Peilung. Jedes Gebiet
  stört anders (kurze Einweisung vor dem Start): Split-Raum ruhig mit Sprüngen, **Glutsee** Sonnenstürme (Rand blinkt
  rot, danach ist das Signal verrutscht), **Schweigendes Band** Echos (mehrere Punkte, Echos stottern und kosten
  Peilung), **Kristallgrenze** Brechung (Punkt versetzt, bis die Frequenz stimmt), **Abgrund** Puls (sendet nur im Takt
  kurz-kurz-lang, dazu ein Echo). Mit dem Erkundungsfortschritt wird es schneller und enger. Manchmal taucht ein
  **Nebensignal** auf (bernsteinfarben): 1,6 s angepeilt, birgt der Späher ein Wrack (25.000 Cr im Split-Raum bis
  500.000 Cr im Abgrund) – die Zeit fehlt aber für die eigentliche Peilung. „Nur schicken“ geht ohne Minispiel.
- **Entwicklerregler auf der Sektorenkarte:** „Spiel“/„Alles“ – zeigt alle Sektoren aufgedeckt (nur Ansicht, der
  Spielstand bleibt unverändert; gemerkt im Browser).
- **Durchbruch:** Eine gefundene Signatur zeigt ein erloschenes Tor. „Baustelle einrichten“ kostet nichts; das Tor
  braucht Waren aus der eigenen Wirtschaft (Glutsee 250 Hüllenteile + 1.000 Energiezellen; Band zusätzlich Mikrochips,
  Kristallgrenze Claytronik und Scannerfelder, Abgrund Claytronik und Quantenröhren – jeweils mehr). „Aus deinen Lagern
  liefern“ nimmt sie aus den Stationslagern (eingestellte Reserven bleiben liegen), „Rest zukaufen“ kauft Fehlendes mit
  40 % Aufschlag. Sind alle Waren da, dauert die Montage 30 min; dann einen Späher hindurchschicken. Erstsichtung: Vollbild-
  Enthüllung (Sechseck zeichnet sich in Licht, füllt sich mit dem Schimmer des Gebiets oder dem Bild
  `src/assets/sektoren/<id>.jpg`, der Name erscheint Buchstabe für Buchstabe) mit einem **Fundstück**: Logbucheintrag,
  Funkspruch oder Notiz, die zusammen die Geschichte der verschwundenen Kolonie Vesh'ara erzählen. Vom neuen Sektor aus
  kann weiter gesucht werden. **Forschungsakte** (Stern-Knopf auf der Sektorenkarte): alle Entdeckungen nach Gebieten mit
  Datum und Fundstück, Unentdecktes als „?“.
- **Spielbare neue Sektoren (`src/data/frontierSectors.ts`, `src/engine/frontierSync.ts`):** Entdeckte Sektoren, die schon
  ausgebaut sind, werden nach der Erstsichtung wie jeder Split-Sektor: hinfliegen, Handelsposten, Rohstofffelder, NPC-Verkehr,
  Aufträge, Baulizenz (ohne Lizenz im Nachbarsektor – man kommt durch das Tor). Sie stehen erst nach der Entdeckung in den
  Sektordaten; ein neues Spiel nimmt sie wieder heraus, Laden hängt sie passend zum Spielstand ein. Bisher spielbar: die
  **Glutsee** – Rhy's Ausblick (Zyarth, Horchposten), Glutsee I (Sonne 1000 %, Wasserstoff/Helium), Die Aschefelder (sehr
  reiches Erz, Nividium), Familie Rhak (Werft, Siedlung) und Der Schmiedestern (Sonne 260 %). Vier davon gehören der
  **Familie Rhak**, einer eigenen Fraktion mit eigenem Ruf (Handel, Aufträge; erscheint im Ruf erst nach ihrer Entdeckung).
  Bilder: `src/assets/sektoren/<id>.jpg` (16:9) – Sektorhintergrund, Erstsichtung und Akte; bis dahin vorhandene Hintergründe.
- **Eigenheiten der Glutsee (`src/engine/phenomena.ts`):** hängen nur an der Spielzeit. **Glutsee I:** alle 3 h ein
  Strahlungssturm (35 min) – Schiffe im Sektor fliegen dann mit 60 %, die Szene zeigt Funkenregen und rötliche Blitze,
  eine Meldung kündigt ihn an. **Die Aschefelder:** Staub – Schiffe immer mit 80 %, Miner fördern 30 % mehr. **Der
  Schmiedestern:** Pulsar – Sonnenlicht schwankt im Zwei-Stunden-Takt zwischen 60 % und 300 % (Solarmodule entsprechend).
  **Horchposten in Rhy's Ausblick:** mit 150 Hüllenteilen, 600 Energiezellen und 300 Veredelten Metallen (aus den Lagern
  oder zugekauft) wieder in Betrieb – dann sind alle Märkte der Glutsee live sichtbar und Suchen dort finden 25 % leichter
  etwas. Kartenkarte und Kopfzeile der Sektoransicht zeigen die Eigenheit (Sturm mit Restzeit, Sonne in Prozent).
- **Keine verlorenen Texte:** Listenzeilen, Feldkacheln und Meldungen brechen um statt mit „…“ abzuschneiden. Wo doch
  gekürzt wird, klappt Antippen den Text auf; auf Knöpfen und antippbaren Zeilen zeigt langes Drücken den ganzen Text in
  einer Blase. `node scripts/clip-audit.mjs [ordner]` öffnet 27 Ansichten und Dialoge in beiden Starts und meldet jede
  noch gekürzte Stelle (läuft im e2e mit).
- **Minispiele im echten Spiel** (zusätzlich zum Menü „Minispiele“, das bleibt):
  **Vorfälle** – etwa einmal je Spielstunde (erst ab Kapitel 5, also nach der geführten Einführung; frühestens nach 40 min Spielzeit, höchstens zwei offen) entsteht aus dem Geschehen ein
  Ereignis, angekündigt als Meldung und als Leiste über dem Kapitelziel mit **„Selbst übernehmen“**:
  *Überfall* auf einen beladenen Frachter (Kampf; Piraten, in der Ravine Xenon, im neuen Raum Kha'ak) – ohne Eingreifen
  gehen nach 20 min 15 % der Ladung verloren, selbst verteidigt nichts, mit drei Sternen dazu 3.000 Cr Kopfgeld.
  *Störung* in einem Produktionsmodul (Rohr-Puzzle) – das Modul läuft mit halber Leistung; gelöst sofort wieder voll,
  sonst nach 90 min Reparatur mit 20 Hüllenteilen. *Reiche Ader* bei einem Miner (Erz- bzw. Gasabbau) – Bonusware ins
  Heimatlager, ohne Eingreifen 15 % eines Laderaums, selbst abgebaut bis 105 % (nur so viel, wie ins Lager passt).
  Selbst spielen ist nie Pflicht. **Aufgaben an Stationen** – in jedem bekannten Sektor bieten zwei Stationen je eine
  Aufgabe an (Werft: Leitungen, Rumpfteile verladen; Wache: Geleit, Xenon-Streife; Habitat: Umladen, Fähre; Handelsposten:
  Eilsendung, Frachtraum, Andockhilfe; Felder: Probebohrung, Gasprobe), alle 3 h neu. Lohn ab einem Stern, nach Sternen:
  Credits (nach Lizenzpreis des Sektors), Modteile und Ruf bei der Fraktion – Ruf aber nur bis Stufe 3 und höchstens
  0,5 je Fraktion und Spieltag (Einstiegshilfe in neuen Sektoren, kein Ersatz für Handel und Aufträge). Zu finden in der
  Sektorinfo unter „Allgemein“ und in der Karte der jeweiligen Station. Ansehen: `node scripts/incident-shot.mjs <ordner>`.
- **Eigenheiten des Split-Raums** (in der Sektorinfo unter „Allgemein“, mit Aushang, Funkspruch oder Logbuch-Zeile aus
  dem Sektor): **Familie Zhin** – Wiederaufbau, die Zhin-Werft zahlt 12 % mehr für Hüllenteile und Claytronik.
  **Familie Tkr** – Stapellauf alle 4 h (erster nach 2 h): eine Stunde lang zahlt die Tkr-Werft 30 % mehr für Hüllenteile,
  Claytronik, Siliziumscheiben, Mikrochips und Scannerarrays. **Tharka's Cascade** – Gasgezeiten: Wasserstoff, Helium und
  Methan geben im Drei-Stunden-Takt 70–150 % her (Knopf „Gas … %“ in der Werkzeugzeile). **Tharka's Ravine** –
  Xenon-Streife alle 5 h für 25 min (erste nach 3 h): Miner ruhen, Schiffe fliegen mit 60 %. **Rhy's Defiance** –
  Patrouillenkorridor, Schiffe fliegen mit 120 %. **Heart of Acrimony** – Kometenschweif, Eis- und Methanfelder wachsen
  doppelt so schnell nach. **Zyarth's Dominion** – Thronmarkt, Thron und Thronwerft zahlen für Schiffstechnik 10 % mehr.
  Sektorbeschreibungen und Kapiteltexte sind konkreter geworden (Namen, Zahlen, Aushänge statt Floskeln).
- **Glutsee I – Sonnenkerne: „Wer die Glutsee hat, hat die Energie.“** 1000 % Sonne, im Strahlungssturm 3000 %.
  Energiezellen sind sperrig und billig – der **Sonnenofen** (Bauplan nur bei der Familie Rhak, Ruf 4, nur ab 500 % Sonne)
  verdichtet sie zu **Sonnenkernen**: je 15 min 25.000 Energiezellen + 5 Silizium → 1 Kern (4 je Stunde, genau die Leistung
  eines Solarkraftwerks bei 1000 % – bei normalem Licht wären es zehn Kraftwerke je Ofen; im Sturm lädt der Ofen dreimal so
  schnell). Ein Kern (25 m³) gibt am Ziel **30.000 Energiezellen** ab und ist mehr wert als seine Vorprodukte. Drei Zwecke:
  1. **Kraftwerk des Imperiums** – jede eigene Station, die Energiezellen verbraucht, nimmt Kerne an (eigene Transporter
  bringen sie) und entlädt einen, sobald Zellen fehlen. 2. **Schlüssel nach oben** – tote Tore brauchen Kerne zum Zünden
  (Schweigendes Band 4, Kristallgrenze 20, Abgrund 60). 3. **Erbe der Vesh'ara** – sie haben im Schmiedestern Sonnenlicht
  verdichtet; das Stille Tor wird am Ende sehr viele Kerne brauchen. Sonnenkerne werden nicht frei gehandelt.
  **Sturm:** Ohne ausreichenden Schutz überhitzen Stationen in Glutsee I: die Produktion steht, zum Wiederanlauf braucht
  jedes Produktionsmodul 25 Hüllenteile. Ein **Kühlmantel** (Rhak, Ruf 3) schützt bis zu 6 Produktionsmodule, jedes
  geschützte Modul verbraucht je Sturm 40 Supraflüssiges Kühlmittel – wer vorgesorgt hat, erlebt im Sturm seine ergiebigste
  Phase. Station und Modulliste zeigen nötige Kühlmäntel, Kühlmittel je Sturm und die Zeit bis zum nächsten Sturm.
- **Szenen-Feinschliff:** Der zerbrochene Mond der Aschefelder läuft am Rand weich aus, ist in Staubfarbe getönt und von
  treibenden Schwaden umgeben (keine harte Kontur mehr). In Glutsee I schlängeln sich langsame Magnetfeldlinien von der
  Sonne weg (im Sturm doppelt so viele und heller) statt schneller Striche. Ansehen: `node scripts/scene-shot.mjs <ordner> [sektor] [storm]`.
- **Mehrschichtige Sektorszenen (`src/render/sceneBg.ts`):** Aus freigestellten Bildebenen (Sterne, Nebel, Sonne, Plasma,
  Felsen) entsteht ein lebendiger Hintergrund: jede Ebene mit eigener Tiefe (Parallaxe beim Verschieben), dazu gezeichnete
  Effekte – funkelnde Sterne, atmender Nebel, Sonne mit pulsierender Korona und langsam drehenden Strahlen, flackernde
  Plasmaschleier, Funken, die von der Sonne fortgetragen werden, sich langsam drehende Felsen im Vordergrund, Vignette.
  Die Anordnung richtet sich nach dem Bildschirm (im Hochformat wird der Nebel gedreht, Sonne und Felsen bleiben am Rand,
  die Mitte ruhig). Ebenen aufbereiten: `node scripts/import-scene.mjs <sektor> sterne=<a.png> nebel=<b.png>:8 sonne=<c.png>:5 …`
  – entfernt grelle Freistellsäume (Farbe aus dem Inneren ausbluten, weich auslaufende Ränder) und speichert in voller
  Auflösung als WebP 0,95 nach `src/assets/szenen/<sektor>/` (bei sauber freigestellten Ebenen `:0` = unverändert).
  Szenen sind Listen aus ganzflächigen Ebenen, Objekten mit Anker und Lage je Format und Effekten (Funkeln, Glühen,
  Strahlen, Funken, Staub, Schwaden, Verkehr, Glimmen, Pulsar-Takt, Vignette). Fertig: die ganze Glutsee.
- **Kampagne „Kanal 9“** (nach „Neue Horizonte“): Tevka Rhy hört auf Kanal 9 ein Knacken aus Richtung des toten Tors.
  Vier Kapitel führen durch Späherkauf, Peilung, Torbaustelle und die erste Erstsichtung (Rhy's Ausblick). Ab hier
  gilt für alle Texte: konkret statt Werbesprache – Namen, Zahlen, Stimmen aus der Spielwelt.
- **Werft als Schauraum (Schiff kaufen):** oben groß das gewählte Schiff in einer Szene, darunter alle Schiffe als
  Draufsicht zum Durchblättern (Größe, Art, Preis, Anzahl im Besitz), Filter Alle/Miner/Transporter, Werte als Balken im
  Vergleich zum stärksten Schiff, Preisaufstellung, Heimatstation; Hinweis, wenn Dock/Pier oder Geld fehlen.
  Szenenbilder: `src/assets/schiffe/<Klasse>.jpg` (z. B. `boa.jpg`, Querformat 16:9, volle Auflösung, JPEG ≥ 0,92) –
  werden automatisch erkannt; fehlt eins, schwebt die Draufsicht vor einem passenden Weltraum-Hintergrund. Die Tuatara
  nutzt vorerst die Bilder der Startwahl.
- **Karrierestart in drei Schritten:** (1) Geschichte – die Sätze erscheinen nacheinander, der letzte hervorgehoben;
  (2) „Vier Dinge, die alles bewegen“ – Bauen, Fördern/Herstellen, Handeln, Kampagne als Karten mit Bild, die
  nacheinander hereingleiten; (3) Schiffswahl im Hangar. Punkte zeigen den Fortschritt, „Weiter“ leuchtet auf, wenn alles
  zu sehen ist; Zurück und Überspringen jederzeit. Nach der Wahl erscheint „Handels-/Schürflizenz erteilt“ mit Startklang.
  Automatisierte Tests springen direkt zur Schiffswahl (außer mit `?intro=1` oder `?welcome=1`).
- **Als App:** Läuft das Spiel unter eigener Adresse (https, nicht eingebettet), ist es installierbar (Manifest,
  Symbol `public/icon-*.png` aus `node scripts/render-icon.mjs`) und offline spielbar (`public/sw.js`: Seite zuerst aus
  dem Netz, Programmteile und Bilder aus dem Zwischenspeicher). Mehr → Spielstand bietet dann „Als App installieren“
  bzw. auf dem iPhone den Weg über „Zum Home-Bildschirm“. Im Claude-Artifact und in der Einzeldatei bleibt das aus.
- **Offline / zum Weitergeben:** `npm run build:einzeldatei` packt alles in eine einzige Datei
  `dist-einzeldatei/index.html`, die sich direkt im Browser öffnen oder aufs Handy kopieren lässt.
- **Entwickeln:** `npm install`, dann `npm run dev` – die angezeigte Netzwerkadresse funktioniert
  auch auf dem Handy im selben WLAN.

Tipp fürs Handy: Seite öffnen → Browsermenü → „Zum Startbildschirm hinzufügen“.

## Was drin ist

| Bereich | Umsetzung |
| --- | --- |

## Offene Punkte

- **Baulimit im Fortschrittsbaum (für später vorgemerkt):** Das Limit von derzeit 100 Modulen je Station stufenweise freischalten – entweder als allgemeiner Fortschritt (z. B. Forschung oder Unternehmensstufe) oder abhängig vom Stationsmanager (Stufe/Eigenschaften, siehe Ereignis-Idee unten). Offen: Stufen und Kosten, Umgang mit Stationen, die schon größer sind.

- **Belegschaft:** Habitatmodule mit Verbrauch von Nahrung und Medizin, damit der Belegschaftsbonus im Planer und in der Simulation vollständig durchgerechnet wird.
- **Erfahrung und Stufen für Schiffe und Stationen (Idee, noch nicht umgesetzt – erst nach dem Test der aktuellen Version):**
  Miner und Stationen sammeln durch ihre Arbeit Erfahrungspunkte (Fahrten, geförderte/verarbeitete Mengen, Verkäufe) und steigen
  im Level auf. Stufen schalten Optimierungen frei – „die Karotte vor der Nase“, mehr Spielfluss und Spieltiefe.
  Beispiel Miner: Standard ist *Nachfüllen* (fliegt mit Restladung wieder los); *Verkaufen*, *Warten* und die *Automatik*
  mit Fallbetrachtung werden erst mit höheren Stufen freigeschaltet. Analog denkbar für Stationen (z. B. Lagersteuerung,
  Reserve, Handelsregeln) und Transporter. Offen: XP-Quellen und Kurve, was genau je Stufe kommt, Anzeige (Stufe/Fortschritt
  im Schiffs- und Stationsblatt), Umgang mit bestehenden Spielständen.
- **Ereignisse mit freiwilligen Minispielen (Minispiele mit Tiefe gebaut, Einbindung offen):**
  Sporadische Ereignisse in den Spielbereichen; der Spieler wird gefragt, ob er ein kurzes Minispiel spielen möchte.
  Ablehnen = kleiner, vorübergehender Malus (z. B. 30 min x % weniger Produktion), Spielen und Lösen = kein Malus und per Zufall
  eine Belohnung (z. B. dauerhafte kleine Effizienzsteigerung oder besondere Gegenstände). So reizvoll, aber nie Pflicht.
  - *Piraten- / Xenon-Überfall:* Draufsicht-Shooter, eigenes Schiff per virtuellem Joystick in alle Richtungen steuern, Feinde
    abschießen. Ausrüstung (Waffen, Schilde, Triebwerke) verbesserbar – passt zur eigenen Werft und zu waffennahen Bauplänen/Waren.
  - *Fabrik-Störung:* z. B. verstopfte Rohrleitung als Rohr-Puzzle (Leitungsstücke drehen/anordnen).
  - *Bergbau:* eigenes Minispiel (z. B. reiche Ader treffen, Asteroid zerlegen).
  Gedanken dazu: Häufigkeit begrenzen (Abklingzeit, höchstens ein offenes Ereignis), Ereignisse während Offline-Zeit/Zeitraffer
  automatisch mit Malus abwickeln oder kurz aufheben; Malus klein und sichtbar (Countdown am Modul), Belohnungen eher selten und
  spürbar; Schwierigkeit mit Fortschritt steigern; kurze Runden (30–90 s), Touch-tauglich, jederzeit abbrechbar (= Malus).
  Verknüpfbar mit der Stufen-Idee oben (Erfahrungspunkte aus Minispielen) und mit Kampfschiffen/Gefahren.
  - *Häufigkeit steuern – Stationsmanager:* Jede Station hat einen Manager mit Stufe und Eigenschaften (z. B. Sorgfalt, Technik,
    Sicherheit). Niedrige Stufe = mehr Störungen; Eigenschaften wirken gezielt (Technik → weniger Rohrbrüche, Sicherheit → weniger
    Überfälle auf die Station). Manager sammeln Erfahrung (Stufen-Idee), lassen sich ggf. anwerben/austauschen.
  - *Häufigkeit steuern – Schutz durch Kampfschiffe:* Begleitschutz für Frachter senkt Überfälle auf Handelsrouten, Patrouillen
    in einem Sektor senken Piraten-/Xenon-Ereignisse dort. Weitere mögliche Effekte: Patrouillen erhöhen Ruf oder Marktsicherheit,
    ungeschützte Routen riskieren Frachtverlust, Geleitschutz kostet Unterhalt (Zielkonflikt Sicherheit vs. Kosten).
    Die Kampfschiffe kommen aus der eigenen Werft und brauchen waffennahe Waren – verbindet Wirtschaft, Werft und Gefahren.
- **Kampfschiffe und Gefahren:** Piraten und Xenon an den Toren, Geleitschutz und Verteidigungsplattformen – die eigene Werft ist die Grundlage dafür.
- **Geld verbrauchen:** Spätestens nach der L-Werft wächst das Vermögen schnell (simulierter Spieler: ~500 Mio Cr nach ~100 h). Kampfschiffe, Kriege und Unterhalt sollen als Gegengewicht kommen.

```
docs/design   Designkatalog (Split-Stil) und Vorgaben für Bildgeneratoren
tests         Simulationstests
scripts       Werkzeuge: Balance-Simulation, Screenshot-Tour, Artifact-Export
```

Alte Spielstände: `tests/fixtures/saves/` enthält echte Spielstände aus 8 älteren Versionen (erste Version bis erstes Baulager), erzeugt mit dem jeweiligen damaligen Code. `npm test` lädt jeden mit dem aktuellen Code, prüft Kampagne, Bauten, Lager und Schiffe und spielt 12 Stunden weiter.

Bilder: `node scripts/import-sprite.mjs <bild.png> <name> [vorschau|-] [größe]` übernimmt ein Bild (z. B. aus ChatGPT) – Hintergrund freistellen, in hoher Qualität als WebP ablegen (1024 px, kleinere Vorlagen in Originalgröße); `node scripts/render-sprites.mjs` rendert die 3D-Modelle aus `scripts/render/` neu (three.js, nur beim Erstellen).

Nützliche Befehle: `npm test`, `npm run typecheck`, `npm run balance` (simulierter Spieler über 72 Spielstunden), `npm run e2e` (Handy-Oberfläche in 390 und 360 px: Werft, Zurück-Taste, keine abgeschnittenen Texte, dazu alte Spielstände über den echten Ladedialog und ein kompletter Durchlauf der ersten Schritte, bei dem immer genau dorthin getippt wird, wohin der Hinweis zeigt, sowie Warenfilter, Problemsymbol-Tipp und Kapitelbanner und alle Minispiele (Einführung, Antippen/Ziehen, Pause per Zurück, Auswertung, Bestwert) – läuft auch in GitHub Actions), `npm run perf` (Simulationstempo), `npm run fps` (Bildrate der Karte), `npm run kampagne -- [seed] [stunden] [--weiter]` (simulierter Spieler spielt alle 28 Kapitel (ca. 100 Spielstunden) und prüft stündlich: keine ungültigen/negativen Bestände, kein überfülltes Lager, kein festhängendes Schiff).
